# Git Commit Rules

このプロジェクトにおいてエージェントがGitコミットを作成する際は、以下のルールを必ず守ってください。

## 1. コミットの分離（スコープの明確化）
- **記事本体の変更**（`articles/*.md` や `books/*.md` など）と、**エージェント用の設定・ルールファイルの変更**（`.agents/*` や `GEMINI.md` など）は、**必ず別々のコミットに分けてください**。
- 例: 記事の更新とルールの更新を同時に依頼された場合、1回の `git commit` でまとめず、それぞれに適切なメッセージをつけて2回に分けてコミットしてください。

## 2. コミットメッセージのプレフィックス
作業内容に応じて、以下のプレフィックスを使い分けてください。また、メッセージはエージェント間の言語ブレを防ぐため**必ず日本語**で記述してください。

### 記事（コンテンツ）に対する変更
- **新規公開の場合:** `docs(publish): <記事タイトル>`
- **更新の場合:** `docs(update): <記事タイトル>`
- **削除の場合:** `docs(delete): <記事タイトル>`

### エージェント設定・ルールに対する変更
- **ルールの追加・修正の場合:** `chore(agent): <変更内容の要約>` または `feat(agent): <変更内容の要約>`

## 3. 複数スコープ変更時のコミット手順例
もし記事とルールの両方を変更した場合は、以下のように分けてコミットを実行します。

```bash
# 1. 記事の変更をコミット
git add articles/1234567890abcd.md
git commit -m "docs(update): データレイクハウスの歴史と最新トレンド

- 既存記事にIceberg記事へのリンクを追加"

# 2. エージェントルールの変更を別でコミット
git add .agents/
git commit -m "chore(agent): Gitコミット分離ルールの追加

- 記事の変更とエージェント設定の変更を別コミットにするルールを定義"
```
